# EX-24 : SBOM pour chaque artefact

- **Source interne** : référentiel interne d'exigences CI/CD, niveau « Obligatoire (ReCyF) + Bonne pratique ».
- **Références citées dans le CSV** : RECYF 5.A.1 ; ESF ; SSDF PS.3.
- **Verbatim du CSV** : « Un SBOM est produit pour chaque artefact et permet d'identifier les composants touchés par une alerte. »

## Vérification des sources

- **SSDF PS.3.2** : **vérifié**. Texte : « Collect, safeguard, maintain, and share provenance data for all components of each software release (e.g., in a software bill of materials [SBOM]). » C'est la source directe du SBOM par release.
- **ReCyF 5.A.1** : **vérifié**, mais le texte porte sur la cartographie des systèmes d'information, pas sur le SBOM. Voir la fiche OF-24.
- **ESF** (NSA, CISA, ODNI, 09/2022) : **non vérifié**. Le PDF officiel a répondu HTTP 403.

## Interprétation retenue (à valider)

Chaque release porte son SBOM, copié lors de la republication. La recherche d'un composant vulnérable doit fonctionner sur les releases comme sur les candidats.

## Où elle est utilisée

- ADR-001, section « Promotion ».
